Privacy Policy

How RAM Manager handles your data — in plain language.

Version 1.1.0 Last updated: October 9, 2026

No data collection

RAM Manager does not collect any personal data. We do not track you, we do not transmit information to external servers, and we do not use analytics or telemetry. The extension works entirely offline and all functionality runs locally on your device.

The short version

  • No analytics, no telemetry, no tracking of any kind.
  • No remote servers — the extension makes zero network calls of its own.
  • Everything it remembers lives in your own browser's storage, on your device.
  • No ads, no data brokers, and your data is never sold.

What is stored locally

The only data the extension keeps is a small amount of JSON inside your own browser storage:

chrome.storage.sync

Your settings, whitelist, and theme choice.

Synced between your own devices by Chrome's built-in sync if you're signed in — never sent to us.

chrome.storage.local

Suspension history (capped at 500 entries), frozen-tab metadata, idle timers, saved sessions (capped at 20), memory-saved estimates.

Stays on this device only.

chrome.storage.session

Keep-awake holds you set from the popup.

Wiped automatically when the browser restarts.

localStorage

Cached light/dark class so pages don't flash the wrong theme; popup section open/closed state.

Page-appearance cache only, on this device.

If you are signed into Chrome with sync enabled, Chrome itself may roam your settings between your devices — that is Chrome's built-in sync, and it never touches any server of ours.

You control your data

You can export your data as JSON, import it back, or clear stats and history at any time from the extension's settings. Because nothing is ever sent to us, there is nothing for us to delete on your behalf — uninstalling the extension removes everything it stored.

Permissions explained

Chrome lists every permission an extension requests at install time. Here is exactly what each one is for, and why it is needed:

tabsRead your tabs

Used to read tab URLs, titles, and states (audible, pinned, active) so the extension can tell which tabs are idle and safe to suspend — and to render the tab list in the popup. The only write it ever makes is navigating a tab to, and back from, the suspended page. That navigation is the entire product.

storageStore data locally

Persists your settings, whitelist, and theme, plus the local-only history and stats shown on the dashboard. Nothing written through this permission is ever transmitted anywhere.

alarmsRun on a schedule

A one-minute heartbeat that checks which tabs have passed their idle threshold. It only runs while auto-suspend is enabled — the feature is off by default.

contextMenusAdd right-click menu items

Adds the "Suspend this tab" and "Suspend other tabs" entries to Chrome's right-click menu. Nothing more.

scriptingInject scripts on demand

A small, local script (shipped inside the extension, never from the internet) is injected into a page only in the instant before an automatic suspension. It draws an on-page warning banner with a "Not now" button, and — only if you enable Form Protection — checks whether a page has unsaved form input. It is never injected at install, never on every page, collects nothing, and cannot execute remote code (the extension's content security policy is script-src 'self').

<all_urls>Access to sites — optional, off by default

This optional permission is requested only at the moment you enable Form Protection, so the unsaved-form check can actually inspect page content. Without it, Form Protection falls back to a URL-pattern heuristic and every other feature works unchanged. You can revoke it at any time from chrome://extensions → RAM Manager → Details.

What we never do

We never sell your data, never show ads, never fingerprint your device, and never load code from a content delivery network. Every line of code that runs ships inside the extension package you installed, and you can read all of it on GitHub.

Favicon loading

When a tab is suspended, the placeholder page may load the original site's favicon so it can display it. This is an ordinary image request — the same as your browser makes when you visit the site yourself. No remote code is executed and no information about you is sent.
